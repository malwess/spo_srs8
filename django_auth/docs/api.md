# Маршруты и REST API

Все примеры получены на учебной базе (`init_demo`) у пользователей student1 и methodist.

## Аутентификация

- API использует **сессию Django** (SessionAuthentication). Сначала выполняется вход на странице
  `/accounts/login/`, после этого браузер передаёт cookie `sessionid` с каждым запросом `fetch()`.
- Без входа любой адрес `/api/...` возвращает `403 {"detail": "Учетные данные не были предоставлены."}`.
- Для POST, PUT, PATCH и DELETE нужен заголовок `X-CSRFToken` со значением cookie `csrftoken`
  (скрипты страниц добавляют его сами). Без заголовка — `403 CSRF Failed`.
- Формат тела запроса и ответа — JSON (`Content-Type: application/json`).

| URL | Назначение | Доступ |
|-----|-----------|--------|

| `/departments/`, `/groups/`, `/courses/` | справочники; `add/`, `<id>/edit/`, `<id>/delete/` — для методиста | вход |
| `/analytics/`, `/analytics/structure/`, `/analytics/performance/` | дашборды | вход |
| `/manager/` | «Менеджер данных» (курсы и факультеты через API) | вход |
| `/tickets/` | «Мои обращения» | вход |
| `/retakes/` | «Пересдачи» | вход |
| `/healthz/` | проверка доступности, ответ `{"status": "ok"}` | все |
| `/admin/` | админка Django | admin |

## Сводка API

| Метод | URL | Назначение | Кто может |
|-------|-----|-----------|-----------|
| GET | `/api/` | корень API со ссылками | вход |
| GET, POST | `/api/departments/` | список (`?search=`, `?ordering=`) и создание факультета | чтение — все, запись — методист |
| GET, PUT, PATCH, DELETE | `/api/departments/<id>/` | факультет | то же |
| GET, POST | `/api/courses/` | курсы (`?search=`, `?department=`, `?ordering=`) | то же |
| GET, PUT, PATCH, DELETE | `/api/courses/<id>/` | курс | то же |
| GET | `/api/categories/` | категории обращений | вход |
| GET, POST | `/api/tickets/` | свои обращения (`?status=`, `?search=`, `?ordering=`), создание | вход, только свои |
| GET, PUT, PATCH, DELETE | `/api/tickets/<id>/` | своё обращение, смена статуса | автор |
| GET | `/analytics/api/<name>/` | данные дашбордов (`overview`, `structure`, `performance`) | вход |
| GET | `/api/retake-slots/` | время пересдач (`?course=`, `?upcoming=1`) | вход |
| GET, POST | `/api/retakes/` | заявки (`?status=`, `?course=`), создание черновика | вход |
| GET, PUT, PATCH, DELETE | `/api/retakes/<id>/` | заявка; изменять и удалять — только автор | автор / методист — чтение |
| POST | `/api/retakes/<id>/submit/` | подать (бронирует место) | автор |
| POST | `/api/retakes/<id>/approve/` | одобрить | методист |
| POST | `/api/retakes/<id>/reject/` | отклонить, тело `{"comment": "..."}` | методист |
| POST | `/api/retakes/<id>/cancel/` | отменить (освобождает место) | автор |
| GET | `/api/retakes/<id>/history/` | история событий | автор, методист |

Общие ответы об ошибках: **400** — неверные данные (ответ — словарь «поле → список сообщений»),
**403** — нет входа, нет прав или нет CSRF-токена, **404** — объекта нет или он чужой,
**409** — удаление нарушило бы связанные данные.

## POST /api/tickets/ — создать обращение

- **Назначение:** студент создаёт обращение в учебный офис; статус всегда «Новое».
- **Аутентификация:** вход обязателен, заголовок `X-CSRFToken`.
- **Тело запроса:**

```json
{"title": "Перенос срока СРС 8", "category": 2, "course": 2,
 "description": "Прошу перенести срок сдачи."}
```

`title` — не менее 5 символов, `category` — обязательно (id из `/api/categories/`),
`course` — необязательно.

- **Успешный ответ — 201 Created:**

```json
{"id": 5, "title": "Перенос срока СРС 8", "description": "Прошу перенести срок сдачи.",
 "category": 2, "category_name": "Перенос срока сдачи работы",
 "course": 2, "course_title": "Базы данных",
 "status": "new", "status_display": "Новое",
 "next_statuses": [{"value": "progress", "label": "На рассмотрении"}],
 "created_at": "2026-11-06T14:39:20.822603+03:00", "updated_at": "2026-11-06T14:39:20.822623+03:00"}
```

- **Типичные ошибки:**
  - 400 — `{"title": ["Тема должна содержать не менее 5 символов."], "category": ["Выберите категорию."]}`;
  - 403 — нет входа или нет CSRF-токена.

## PATCH /api/tickets/<id>/ — изменить обращение или статус

- **Назначение:** изменить тему или описание либо перевести на следующий статус.
- **Аутентификация:** вход, только автор; `X-CSRFToken`.
- **Тело запроса:** `{"status": "progress"}` (переходы только по порядку: new → progress → done).
- **Успешный ответ — 200 OK:** обращение целиком, как в POST, с новым `status`.
- **Типичные ошибки:**
  - 400 — `{"status": ["Недопустимый переход статуса: «Новое» → «Выполнено». Обращение проходит этапы по порядку: Новое → На рассмотрении → Выполнено."]}`;
  - 404 — `{"detail": "No Ticket matches the given query."}` — обращение другого пользователя.

## GET /api/courses/ — список курсов с фильтрами

- **Назначение:** список курсов с количеством студентов, оценок и средним баллом.
- **Аутентификация:** вход обязателен.
- **Параметры:** `search` (название, описание, факультет), `department` (id), `ordering`
  (`title`, `students_count`, `grades_count`, `avg_grade`, со знаком `-` — по убыванию).
- **Пример:** `GET /api/courses/?search=баз&department=1&ordering=-avg_grade` → **200 OK**

```json
[{"id": 2, "title": "Базы данных",
  "description": "Реляционная модель, SQL-запросы и проектирование таблиц.",
  "department": 1, "department_name": "Информационные технологии",
  "students_count": 16, "grades_count": 71, "avg_grade": 3.732394366197183}]
```

- **Типичные ошибки:** 403 без входа. Запись (POST, PUT, PATCH, DELETE) для студента —
  `403 {"detail": "Изменять данные может только методист. Войдите под учётной записью методиста."}`;
  неверные данные у методиста — `400 {"title": ["Введите название курса."], "department": ["Такого факультета нет в базе."]}`.

## DELETE /api/departments/<id>/ — удалить факультет

- **Назначение:** удалить факультет без привязанных курсов.
- **Аутентификация:** методист, `X-CSRFToken`.
- **Успешный ответ:** 204 No Content.
- **Типичные ошибки:**
  - 409 — `{"detail": "Нельзя удалить факультет «Информационные технологии»: к нему привязано курсов — 5. Сначала перенесите курсы на другой факультет или удалите их."}`;
  - 403 — пользователь не методист.

## GET /api/retake-slots/?upcoming=1 — время пересдач

- **Назначение:** будущие пересдачи с количеством свободных мест (для формы заявки).
- **Аутентификация:** вход обязателен.
- **Успешный ответ — 200 OK:**

```json
[{"id": 10, "course": 1, "course_title": "Веб-программирование",
  "starts_at": "2026-11-13T12:00:00+03:00", "room": "412",
  "capacity": 5, "booked": 0, "free": 5}]
```

## POST /api/retakes/ — создать заявку на пересдачу

- **Назначение:** создать черновик заявки. Место пока не бронируется.
- **Аутентификация:** вход, `X-CSRFToken`.
- **Тело запроса:** `{"slot": 10, "reason": "Пропустила контрольную по болезни"}`
  (`reason` — не менее 10 символов).
- **Успешный ответ — 201 Created:**

```json
{"id": 11, "owner_name": "student1", "slot": 10,
 "slot_info": {"id": 10, "course_title": "Веб-программирование", "starts_at": "2026-11-13T12:00:00+03:00",
               "room": "412", "capacity": 5, "booked": 0, "free": 5},
 "reason": "Пропустила контрольную по болезни",
 "status": "draft", "status_display": "Черновик", "comment": "",
 "actions": [{"name": "submit", "label": "Подать"}, {"name": "cancel", "label": "Отменить"}],
 "created_at": "2026-11-06T14:35:03.493619+03:00", "updated_at": "2026-11-06T14:35:03.493637+03:00"}
```

- **Типичные ошибки:**
  - 400 — `{"slot": ["Выберите время пересдачи."], "reason": ["Опишите причину подробнее — не менее 10 символов."]}`;
  - 400 — `{"slot": ["Эта пересдача уже прошла — выберите другое время."]}`, «На эту пересдачу не осталось
    свободных мест.», «У вас уже есть поданная заявка на пересдачу по курсу …».

## POST /api/retakes/<id>/submit/ — подать заявку

- **Назначение:** перевести черновик в статус «Подана» и забронировать место. Статус заявки,
  счётчик мест и событие истории сохраняются в одной транзакции.
- **Аутентификация:** вход, только автор, `X-CSRFToken`. Тело не нужно.
- **Успешный ответ — 200 OK:** заявка со `"status": "submitted"`, в `slot_info` — `"booked": 1, "free": 4`,
  в `actions` остаётся только «Отменить».
- **Типичные ошибки:**
  - 400 — переход не из черновика: `{"status": "Недопустимый переход: заявку в статусе «Подана» нельзя «подать». ..."}`;
  - 400 — нет мест или пересдача прошла (см. POST);
  - 403 — заявка другого пользователя у методиста: «Это действие может выполнить только автор заявки.»

## POST /api/retakes/<id>/approve/ и /reject/ — решение методиста

- **Аутентификация:** только методист, не по своей заявке.
- **Тело:** approve — не нужно; reject — `{"comment": "причина"}` (обязательно).
- **Успешный ответ — 200 OK:** заявка со статусом `approved` или `rejected`; при отклонении место освобождается.
- **Типичные ошибки:** 403 у студента — `{"detail": "Одобрять и отклонять заявки может только методист."}`;
  400 — `{"comment": "Укажите причину отклонения."}`; 404 — заявки нет.

## Изменение статуса через PATCH запрещено

`PATCH /api/retakes/<id>/` с полем `status` → `400 {"status": "Статус нельзя изменить через PATCH/PUT — используйте действия submit, approve, reject или cancel."}`

## Проверка из консоли браузера

После входа откройте DevTools → Console:

```js
const csrf = document.cookie.match(/csrftoken=([^;]+)/)[1];
await fetch('/api/tickets/', {method: 'POST',
  headers: {'Content-Type': 'application/json', 'X-CSRFToken': csrf},
  body: JSON.stringify({title: 'Проверка API', category: 4})}).then(r => r.status);   // 201
```
